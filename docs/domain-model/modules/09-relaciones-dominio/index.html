Módulo 09 · Estructura

Relaciones del Dominio

Trece diagramas — cardinalidad, ownership y navegación permitida/prohibida para cada relación real del ecosistema.

Resumen de cardinalidades

RelaciónCardinalidadOwnership
Usuario — Diagnóstico1 : NUsuario es dueño; un Diagnóstico nunca sobrevive sin su Usuario
Usuario — Workout1 : NUsuario es dueño; cascade delete real (on delete cascade)
Workout — Slot1 : N (contenido)Workout es dueño físico (jsonb)
Slot — Prescripción1 : 1Reemplazo atómico, nunca edición parcial
Usuario — EventoProgresión1 : NUsuario es dueño; append-only
Cliente — Medición1 : N (por referencia, no contención)Cliente NO es dueño físico — Medición es su propio aggregate (08)
Cliente — EnlacePúblico1 : N histórico, 1 : 0..1 activoÍdem — por referencia
Usuario — ClienteNingunaNo existe relación de dominio — solo comparten la noción de "Entrenador" como rol (02)

Navegación permitida y prohibida

NavegaciónPermitida
Medición → ClienteSí, vía clienteId
Cliente → sus MedicionesSí, vía consulta explícita (nunca carga automática, BC-01)
Slot → EjercicioSí, solo por Patrón×Rol, nunca por nombre directo (P7)
Cliente → Workout/ProgramaProhibida — no existe relación de dominio (diagrama 13)
Progression Engine → estado interno de Motor BPSProhibida — solo consume su contrato de invocación (02)
Cualquier entidad → SeñalFatiga crudaProhibida salvo Recovery Engine mismo (P8)
