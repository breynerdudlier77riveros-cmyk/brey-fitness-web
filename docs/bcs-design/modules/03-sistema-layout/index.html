Módulo 03 · Sistema visual

Sistema de Layout

Grid, espaciado, contenedores y breakpoints — heredados del App Shell real de BREY (AppShell.tsx), no reinventados para el BCS.

Heredado heredado

El BCS vive dentro del App Shell privado ya construido (src/components/app/AppShell.tsx): sidebar colapsable persistida en localStorage, header fijo, contenedor max-w-5xl centrado con px-4 md:px-8 py-6 md:py-10. El dashboard del entrenador (07) no introduce un layout nuevo — es contenido dentro de ese contenedor ya existente.

La vista pública del cliente (08) usa el mismo ancho máximo de 1024px pero SIN el sidebar del entrenador — es un contenedor centrado de página completa, consistente con que nunca comparte componente de navegación con el panel privado (BCS Handbook, 01, IN-A1).

Breakpoints

NombreAnchoComportamiento del BCS
Mobile<640pxSidebar oculto tras menú, 1 columna, Dashboard prioriza tarjetas de cliente sobre gráficos
Tablet (sm–md)640–1023px2 columnas de Metric Cards, sidebar aún colapsable
Desktop (lg+)≥1024pxSidebar expandido por defecto, 3 columnas, TOC lateral disponible en pantallas de documentación
Ultra wide (2xl+)≥1536pxEl container permanece en 1024px, nunca se estira — más espacio en blanco a los lados, nunca más columnas de las especificadas (Respiración, 01; decisión formal en BCSD-ADR-05, 20)

Contraejemplos

  • El Dashboard NUNCA excede max-w-5xl en ninguna resolución — una pantalla ultra wide no gana más columnas, gana más margen.
  • La vista pública del cliente NUNCA renderiza el sidebar del entrenador, ni siquiera oculto en el DOM.
