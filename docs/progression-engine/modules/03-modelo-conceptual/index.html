Módulo 03 · Modelo

Modelo Conceptual

Las entidades que el Progression Engine reconoce, sus campos, sus relaciones, y — con la misma importancia — qué entidades del sistema BREY este motor deliberadamente NO conoce.

Objetivo

Fijar el vocabulario exacto del dominio antes de especificar ninguna regla. Toda regla PE-XXX del módulo 07 en adelante usa exclusivamente los términos definidos aquí — ninguna introduce un concepto nuevo sin actualizar primero este módulo.

Entidades reconocidas

EntidadDefinición
SlotUna posición dentro de una sesión prescrita, identificada por Patrón×Rol (P7) — no por ejercicio con nombre. Es la unidad mínima que el motor progresa.
Cadena de progresiónSecuencia ordenada de eslabones para un Slot, propiedad de la Knowledge Base. El motor solo conoce la posición del usuario en la cadena (el eslabón actual), nunca el contenido de los eslabones.
Prescripción vigenteEl conjunto {peso, repeticiones, series, tempo, descanso, RPE objetivo, RIR, duración, volumen, densidad} asignado a un Slot para el próximo ciclo — la salida principal de la microprogresión (08).
Ventana de historialSecuencia ordenada de apariciones pasadas registradas de un mismo Slot (workout_logs reales, nunca prescripciones no ejecutadas). Tamaño mínimo exigido por IN-P3 (02) para cualquier decisión macro.
ApariciónUn registro puntual: el Slot se ejecutó una vez, con sus valores reales logueados (peso real, reps reales, RPE reportado, cumplimiento). Es el átomo de la ventana.
Veredicto de RecoveryDTO de entrada, ya resuelto por el Recovery Engine: {procede: boolean, tipo: "normal"|"descarga", razon: string}. El motor lo consume, nunca lo calcula (10).
Decisión microSalida del motor a nivel de Slot: nueva Prescripción vigente + razón + contexto.
Decisión macroSalida del motor a nivel de jerarquía: avanza / sostiene / retrocede un escalón entre {Microciclo, Mesociclo, Bloque, Nivel} + razón + contexto (09).
Señal de estancamientoMarca no vinculante, adjunta a una Decisión, indicando que un Slot cumple el patrón de estancamiento del módulo 11 — no es una Decisión por sí sola, es metadata de una.
EventoRegistro inmutable de que el motor tomó una Decisión — persistido por el Motor BPS, nunca por este motor (14).

Entidades explícitamente NO reconocidas

Entidad de BREYPor qué este motor no la conoce
Ejercicio (nombre, video, equipamiento)Pertenece a la Knowledge Base — el motor solo ve Patrón×Rol y posición en cadena (P7)
Track, SistemaFuera de la autoridad de este motor — ver 09 "No alcance"
Dolor, Fatiga percibida cruda, Horas de sueñoSeñales crudas de Recovery — el motor solo ve el Veredicto ya resuelto (10)
Usuario (perfil, objetivo, lesiones)El motor opera sobre un Slot ya resuelto para ese usuario — no personaliza dos veces lo que el Diagnóstico y el Generador ya resolvieron

Invariantes del modelo

  • IN-M1: una Aparición es inmutable una vez registrada — el motor nunca reescribe historial, solo lo lee.
  • IN-M2: una Prescripción vigente pertenece exactamente a un Slot y es reemplazada atómicamente, nunca editada parcialmente.
  • IN-M3: una Señal de estancamiento no existe sin una Decisión que la contenga — no es una entidad de primera clase persistible por separado.
  • IN-M4: el Veredicto de Recovery es de solo lectura para este motor — ninguna regla PE-XXX puede producir un Veredicto, solo consumirlo.

Preguntas abiertas de este módulo

Ninguna a nivel de modelo — las preguntas abiertas específicas de mecánica (frecuencia de recálculo de cadena, representación de eslabones parciales) se documentan en el módulo 19, donde se agregan todas las del handbook.
