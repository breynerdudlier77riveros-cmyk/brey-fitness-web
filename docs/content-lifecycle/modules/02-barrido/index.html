Los cuatro falsos positivos que cambian el resultado

Sin verificación en contexto, el barrido diría lo contrario

Cuatro términos aparecen con volumen suficiente para sugerir que el ciclo de vida está documentado. Ninguno lo está:

  • review / revisión (30 y 22 archivos) → Architecture Review, el documento de auditoría del ecosistema. No hay ni una revisión editorial de contenido.
  • status (17) → códigos HTTP del API Contract. No hay estado de entrada.
  • historial (113) y vigente (82) → historial de entrenamiento del usuario y prescripción/eslabón vigente. No hay historial ni vigencia de entrada.
  • archivado (31) y ciclo de vida (13) → Cliente del BCS y entidades del dominio. No hay archivado ni ciclo de vida de entrada.

Resultado del barrido

Lo que existe para el ciclo de vida de una entrada

Tres mecanismos, y ninguno es un ciclo de vida:

  1. Versión de catálogo (15 archivos) — BPS-023 · ADR-009. Versiona el catálogo completo, no la entrada.
  2. Supersesión de ADR (1 archivo) — "revertir una requiere un ADR nuevo que la supersede, nunca edición silenciosa". Aplica a documentos.
  3. Regla de Inmutabilidad (R-2) — protege lo ya generado de cualquier cambio de catálogo.

Lo que no existe: estados, transiciones, aprobación, revisión, publicación, despublicación, retirada, rollback, versionado por entrada y auditoría de decisiones editoriales. Cada ausencia está confirmada con recuento cero de palabra completa.
