Convenciones de Responses

Una única estructura de respuesta para todo el catálogo (07) — extiende, sin sustituir, el Resultado<T> ya especificado por el Architecture Handbook (11) y el envelope { ok, error } ya real en los dos Route Handlers existentes.

Extiende Resultado<T> (Architecture Handbook, 11) Extiende { ok, error } real (app/api/lead)

Estructura única

CampoPresente cuandoForma
okSiempreboolean — obligatorio, primer campo, nunca ausente
dataok: true y la operación devuelve un cuerpo (toda Query; todo Command que crea/transforma un recurso)El Output DTO correspondiente (08) — objeto único o arreglo
errorok: falsestring — código corto, snake_case o SNAKE_CASE según origen (09) — nunca un mensaje libre para el usuario final

Success

Toda respuesta exitosa lleva ok: true. Una Query que no encuentra nada no es un error — devuelve ok: true, data: null (recurso único) o ok: true, data: [] (lista), nunca un 404 disfrazado de éxito ni un error de dominio (Architecture Handbook, 11: "los repositorios no deciden"). La única excepción real es GET /reportes/{token} con un token inexistente o revocado — ahí sí es ok: false (09), porque el propio BCS Handbook (10) decide tratar "no existe" y "revocado" como el mismo error de acceso, no como una lista vacía.

Error

Toda respuesta con ok: false lleva un error no vacío y un status HTTP coherente con él (04) — nunca uno sin el otro (Engineering Handbook, 06). El código de error nombra qué falló, nunca cómo se sintió fallar: PERFIL_INCOMPLETO, no "faltan datos".

Metadata

meta nunca duplica un campo que ya está en data — existe solo para información sobre la respuesta misma: versión de catálogo usada por el Workout Generator, cursor de paginación, o el fecha_ciclo con el que se evaluó una Progresión (determinismo, 01).

Paginación

Ningún endpoint pagina hoy salvo donde el volumen real lo exige — el único umbral especificado es Mediciones del BCS: más de 50 activa paginación de 20 por página, por rango de fecha, no por offset/límite genérico (Performance Handbook, Engineering 09; BCS Handbook, 12).

Campo de metaForma
cursor_siguientestring | null — null cuando no hay más páginas
tamano_paginanumber — 20 por defecto para Mediciones (único valor real especificado)
total_estimadonumber | null — opcional, solo si el repositorio ya lo calcula sin costo adicional

Timestamps

Todo timestamp de una response es UTC ISO-8601 (01) — created_at, fecha, fecha_ciclo. Ninguna respuesta incluye una representación ya localizada a zona horaria del cliente.

Warnings

Existen porque el dominio ya especifica validaciones no bloqueantes — ej. la matriz cruzada de variables del BCS: "Masa grasa + Masa libre de grasa ≈ Peso (±0.5kg)" es advertencia, no bloqueo; solo "cualquier variable de masa > Peso total" es error bloqueante (422, BCS Handbook, 03). warnings es el único canal de este contrato para ese tipo de señal — nunca se codifica una advertencia como si fuera un error.
