Módulo 09 · Acceso y datos sensibles

Compartición

El flujo humano de compartir un reporte: quién lo inicia, cómo, y qué ocurre cuando algo sale mal (se comparte a la persona equivocada, se necesita revocar). El diseño técnico del enlace en sí vive en 10.

Quién comparte y cómo

Únicamente el entrenador puede generar (UC-07, 02) y compartir un enlace. La compartición es manual: el sistema entrega la URL para que el entrenador la copie y la envíe por el canal que prefiera (WhatsApp, email, mensaje de texto) — BCS no envía el enlace en nombre del entrenador en v1, no integra ningún proveedor de mensajería. Es una decisión de alcance explícita, no una limitación técnica no considerada.

Un enlace activo por cliente

Invariante de compartición

Un Cliente tiene como máximo un EnlacePúblico en estado activo a la vez. Generar un enlace nuevo para un Cliente que ya tiene uno activo revoca automáticamente el anterior (09-IN-1) — nunca coexisten dos enlaces activos válidos para el mismo Cliente. Esto simplifica el modelo mental del entrenador ("el enlace de Juan" es siempre uno solo) y reduce la superficie de tokens válidos en circulación.

Flujo de compartición y regeneración

Generar, compartir, y regenerar tras un error de destinatario
sequenceDiagram
  participant E as Entrenador
  participant S as BCS
  E->>S: genera enlace para Cliente "Ana"
  S->>S: crea EnlacePúblico A (activo)
  S-->>E: URL de Ana
  E-->>E: comparte por WhatsApp (canal externo, fuera del sistema)
  note over E: se dio cuenta de que compartió a un número equivocado
  E->>S: revoca enlace de Ana
  S->>S: EnlacePúblico A → revocado
  E->>S: genera enlace nuevo para Ana
  S->>S: crea EnlacePúblico B (activo), distinto token
  S-->>E: nueva URL de Ana

Casos límite

CasoComportamiento
Entrenador comparte el enlace por error a alguien que no es el clienteÚnica mitigación disponible es revocar y regenerar (09-IN-1) — el sistema no tiene forma de "deshacer" un envío ya hecho por un canal externo, y no pretende tenerla
Entrenador genera un enlace para un Cliente archivadoPermitido — archivar no impide compartir (02); si se quiere impedir el acceso, la acción correcta es revocar el enlace, no archivar el cliente
Entrenador pierde la URL antes de compartirlaPuede volver a consultarla desde el panel mientras el enlace siga activo — no requiere regenerar

Contraejemplos

  • El sistema NUNCA envía el enlace por email/SMS automáticamente en v1 — toda compartición pasa por la acción manual del entrenador.
  • El sistema NUNCA permite dos enlaces activos simultáneos para el mismo Cliente.
