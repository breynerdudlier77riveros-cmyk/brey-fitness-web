Módulo 00 · Fundamentos

Introducción

El Motor BPS es el orquestador del sistema de entrenamiento de BREY: el componente que mantiene la respuesta única a "¿en qué estado está este usuario y qué corresponde hacer ahora?". Este handbook lo especifica por completo — un ingeniero debe poder implementarlo sin hacer una sola pregunta. Si el código lo contradice, el código está mal.

Autoridad: handbook > código Especifica, no implementa Profundiza el módulo 07 del Architecture Handbook

Relación con el Architecture Handbook v1.0

Este documento es la especificación profunda del componente que el BREY Architecture Handbook v1.0 (documento hermano, docs/handbook/) define a nivel de sistema en su módulo 07. La jerarquía de autoridad es: Architecture Handbook (marco: principios P1–P16, jerarquía de 15 capas, ontología, contratos) → este handbook (el Motor BPS en detalle) → código. Donde este documento va más allá del marco, lo hace como extensión declarada — las cuatro extensiones nuevas están listadas en el informe de autoauditoría y en el módulo 15. Ninguna contradice el marco; si alguna vez una lo hiciera, se resuelve por ADR, nunca por deriva.

Qué es el Motor BPS

El Motor BPS es una máquina de estados determinista con un ciclo de orquestación semanal. Sus cuatro trabajos, y solo estos:

  1. Activar: traducir el resultado del Diagnóstico en un Sistema/Nivel activos, exactamente una vez, en el momento correcto (compra confirmada — módulo 06).
  2. Custodiar el estado: mantener y transicionar la máquina de estados del usuario (módulo 05), emitiendo un evento con razón por cada transición.
  3. Verificar gates: impedir la generación de entrenamiento cuando faltan datos de seguridad (Diagnóstico, Perfil deportivo) — nombrando exactamente qué falta.
  4. Orquestar: consultar Recovery Engine y Progression Engine en orden fijo e invocar al Workout Generator con el resultado (módulo 07, pipeline; módulo 08, conflictos).
