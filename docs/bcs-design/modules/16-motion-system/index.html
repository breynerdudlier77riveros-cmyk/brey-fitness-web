Motion System

El ritmo de movimiento del BCS es el mismo que ya existe en BREY — 300–500ms, discreto, nunca decorativo. Este módulo formaliza ese ritmo y lo extiende a los componentes nuevos (06).

Ritmo heredado heredado

InteracciónDuración real en el código
Hover de tarjeta (cardStyles.interactive)300ms
Transición de la barra de progreso (Progress.tsx)500ms — el ritmo "pausado" de referencia del sitio
Hover/active de botón (Button.tsx)200ms, escala 1→1.03 (hover) / 0.98 (active)
Transición por defecto de Tailwind (no usada como estándar del sitio)150ms — considerada "rápida", reservada para micro-ajustes, no para el ritmo principal

Curvas de animación

CurvaUso
ease-outElementos que entran (Toast, Skeleton→contenido real)
ease-in-outTransiciones de estado bidireccionales (hover que puede revertirse)
cubic-bezier(0.16, 1, 0.3, 1)Heredada de msg-in en globals.css — reservada para entradas con más carácter (aparición de un mensaje/notificación), no usada en microinteracciones de datos

Cuándo animar

  • Al cargar una barra de rango (10) por primera vez — una única vez.
  • Al expandir/colapsar una History Card o Accordion.
  • Al aparecer un Toast de confirmación.
  • Hover/active en elementos interactivos (Button, Card interactiva).

Cuándo NO animar

  • Actualización de datos en tiempo real de un gráfico de tendencia — un re-render de datos nuevos nunca reanima toda la curva desde cero, evita distraer de lo que realmente cambió.
  • Skeletons — el pulso es sutil (opacidad, no movimiento de posición) para no generar más ruido visual del que ya implica un estado de carga.
  • Ninguna animación en la exportación a PDF/impresión (14) — es un medio estático por definición.
  • Ningún elemento de la vista pública del cliente (08) usa animaciones de entrada llamativas al cargar — el tono es de documento profesional, no de producto consumer con "wow factor".

Movimiento reducido heredado

Toda animación de este sistema respeta prefers-reduced-motion a través del mismo mecanismo centralizado ya establecido en layout.tsx (MotionConfig reducedMotion="user" para lo que use la librería Motion, y la clase utilitaria motion-reduce: de Tailwind para las transiciones CSS puras de Button/Card). Ningún componente nuevo del BCS (06) implementa su propio chequeo de esta preferencia — se apoya en el mecanismo ya existente.
