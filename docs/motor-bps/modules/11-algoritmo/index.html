Módulo 11 · Reglas

Algoritmo conceptual

Los cuatro procedimientos del Motor en pseudocódigo de alto nivel — decisiones, subprocesos, bucles y condiciones, sin ningún detalle de implementación. Cada línea referencia la regla que la gobierna: el pseudocódigo es un índice ejecutable del handbook, no una fuente nueva de verdad.

Procedimiento 1 — activarSistema

PROCEDIMIENTO activarSistema(evento_compra):
  // Idempotencia (BPS-014 análoga / 06)
  SI yaProcesada(evento_compra.transaccionId) ENTONCES RETORNAR respuestaOriginal()

  validar(evento_compra)                                  // 03/V-1 — sistema disponible, forma correcta
  resultado ← diagnosisVigente(usuario, evento_compra.sistemaSlug)   // vigencia 6 meses (06)

  SI resultado no existe O expirado ENTONCES
    registrarCompraEnEspera(evento_compra)
    transicionar(T4, razon)                               // pendiente_diagnostico — BPS-003: sin nivel por defecto
  SI NO
    escribirPunteros(sistema, resultado.nivelEntrada)     // atómico con el evento — BPS-010
    emitirEvento(activacion, razones: resultado.razones, contexto: {transaccionId, version})
    transicionar(T3, razon)                               // pendiente_perfil

Procedimiento 2 — cicloSemanal

PROCEDIMIENTO cicloSemanal(usuario, fechaCiclo, versionCatalogo):   // ambos parámetros obligatorios — BPS-022/023
  SI estado(usuario) ∉ {activo, en_descarga} ENTONCES RETORNAR sinEfectos   // BPS-013

  perfil ← leerPerfilFresco(usuario)                     // BPS-005 / IN-6
  SI gatesIncompletos(perfil) ENTONCES RETORNAR transicionar(T7, faltantes)   // BPS-004/020
  SI diasSinLog(usuario, fechaCiclo) >= 21 ENTONCES RETORNAR transicionar(T11)  // BPS-025 — antes de consultar motores

  ventana ← leerVentanaHistorial(usuario)                // lectura, no interpretación — BPS-019
  veredicto ← RecoveryEngine.evaluar(ventana, mesocicloActual)     // SIEMPRE primero — BPS-007

  SI veredicto.exigeDescarga ENTONCES
    transicionar(T8, veredicto.razon)                     // Progression NO se calcula este ciclo
  SI NO
    decision ← ProgressionEngine.evaluar(ventana, prescripcionVigente, veredicto)
    aplicarTransicion(decision)                           // avanza/sostiene/retrocede + evento con contexto
    SI estado era en_descarga ENTONCES transicionar(T9)

  SI finDelUltimoBloque(estructuraCatalogo, posicionUsuario) ENTONCES RETORNAR transicionar(T14)  // BPS-018

  SI semanaYaGenerada(usuario, microcicloSiguiente) ENTONCES RETORNAR laExistente   // BPS-014
  plan ← WorkoutGenerator.generarSemana(microciclo, perfil, prescripcion, veredicto, versionCatalogo)
  SI plan es error ENTONCES RETORNAR propagar(plan)      // CATALOGO_INSUFICIENTE — BPS-021: jamás parchear
  emitirEvento(semana_generada, contexto: {versionCatalogo, tipoSemana})
  RETORNAR plan

Subproceso — transicionar (usado por todo lo anterior)

SUBPROCESO transicionar(T, razon):
  SI NO guardValido(estadoActual, T) ENTONCES RETORNAR anomalia(estadoActual, T)   // tabla del módulo 05
  // Atómico: puntero + evento juntos, o nada — BPS-010
  atomicamente:
    estadoActual ← destino(T)
    emitirEvento(transicion_estado, razones: razon, contexto: {origen, destino, disparador, guard})

Procedimiento 3 — recomputarEstado (recuperación)

Especificado en el módulo 05 — replay determinista y total sobre la secuencia de eventos, con la propiedad IN-5. No se duplica aquí (una sola fuente por tema).

Procedimiento 4 — flujo de onboarding

Es la composición secuencial de los pasos 1–8 del módulo 07: no tiene lógica propia más allá de encadenar activarSistema → gates → primer cicloSemanal. Se declara para completitud: no existe un quinto procedimiento — todo comportamiento del Motor es alcanzable desde estos cuatro.

Propiedades exigibles a cualquier implementación

PropiedadTest conceptual

IdempotenciaEjecutarlo dos veces seguidas: la segunda es no-op (SEMANA_YA_GENERADA / guards)
Atomicidad de transiciónNo existe ejecución que deje puntero sin evento o viceversa
