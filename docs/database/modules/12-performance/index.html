Cache

Sin cache en ningún punto del sistema — confirmado

Cero ISR, cero revalidate, cero memoización (Performance Handbook, Engineering 09). El caso de mayor riesgo de crecimiento sin mitigación es el Reporte del BCS: se recomputa on-demand sobre el historial completo cada vez (IN-D3) — el propio BCS Handbook (12) proyecta "cientos de Mediciones" por Cliente, y el Engineering Handbook confirma cero estrategia de cache. Cachear el cálculo del Reporte, con invalidación al registrar una nueva Medición, es la mitigación más directa — pero no se implementa aquí, ni se decide en este documento cuándo activarla (16).

Materialización — el único caso real del ecosistema

profiles.sistema_actual y profiles.nivel_actual son la única materialización real de un cálculo derivable en todo el ecosistema — un puntero de estado mantenido para que cada lectura de "¿en qué Sistema/Nivel está este Usuario?" sea una lectura de una sola fila, nunca un replay completo de progression_events (01, MBPS-ADR-01). Ningún otro dato derivado (Programa, Bloque, Mesociclo, Reporte, EstadoRecuperación) se materializa — todos se calculan en el momento de la lectura (Domain Model Handbook, 13). La diferencia entre el Usuario (sí se materializa) y el Reporte (no se materializa) es la frecuencia de lectura frente al costo de invalidación: el puntero de Usuario se lee en cada request; el Reporte, solo cuando alguien lo visualiza.
