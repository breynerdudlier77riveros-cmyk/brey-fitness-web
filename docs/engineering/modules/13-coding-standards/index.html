Coding Standards

Cada regla de este módulo se extrajo del código real y verificó consistente en múltiples archivos — no es una preferencia de estilo importada de otro proyecto.

Componentes y Hooks

Un componente de brand/ envuelve una primitiva de ui/ vía React.forwardRef cuando la primitiva original expone un ref (patrón consistente en Card, Progress, CardTitle) — nunca se pierde el ref al envolver. Un hook custom vive junto a su único consumidor mientras sea el único (03, FE-04) — no se extrae preventivamente a una carpeta hooks/ antes de tener un segundo caso de uso real.

Services, Repositories, DTO

Ya cubierto en detalle en 04 y 06 — la regla de naming aplicable aquí es que un repositorio nunca lleva el sufijo Service ni Repository en el nombre del archivo cuando la carpeta ya lo indica (lib/profile/repository.ts, no lib/profile/ProfileRepository.ts) — el path ya es parte del nombre.

Enums, Interfaces, Tipos

Regla real, sin excepciones encontradas

BREY no usa enum de TypeScript en ningún archivo auditado — usa type X = 'a' | 'b' | 'c' (union de string literals). Misma filosofía que la elección de text + CHECK sobre CREATE TYPE ENUM en Postgres (05): una unión de literales se extiende añadiendo un valor a la lista, sin la semántica adicional (y las sorpresas de comparación/serialización) de un enum nativo de TS.

Imports

Alias @/* → src/* (definido en tsconfig.json) para cualquier import fuera del propio directorio — nunca rutas relativas largas (../../../lib/...). Dentro del mismo directorio o un nivel abajo, ruta relativa simple (./Button) es aceptable y preferida sobre el alias.

Comentarios

La convención más distintiva del código real de BREY

Todo comentario no trivial explica por qué, nunca qué — el código ya dice qué hace. Ejemplos reales: el comentario de numOrNull() no describe la función, describe la trampa de PostgREST que la motiva; el comentario de cardStyles.interactive en Card.tsx explica por qué la animación es CSS puro y no Motion (evitar convertir cada call site en Client Component). Un comentario que solo repite el nombre de la función en prosa se elimina en revisión.

Errores, Async, Promises

Toda función que accede a Supabase es async con await explícito — sin .then() encadenado en el código de dominio. Un repositorio nunca lanza (throw) ante un error esperado de datos ausentes — devuelve null (FT-05, 06); throw se reserva para errores de programación (parámetro inválido en tiempo de desarrollo), no para condiciones de negocio esperables como "el perfil no existe todavía".

Organización

Un archivo de dominio (lib/<dominio>/) concentra todo lo relacionado con ese dominio hasta que crece lo suficiente para dividirse (FT-11, umbral ya especificado en 03 para types.ts/utils.ts) — nunca se crea una subcarpeta especulativa para un dominio con un solo archivo pequeño.
