Módulo 08 · Garantías

Trazabilidad

El módulo más crítico del handbook. P14 exige que la responsabilidad "pueda rastrearse a una decisión humana"; de los seis datos que esa exigencia implica, uno se registra y cinco no tienen dónde.

La exigencia

P14 · Motivación

"La responsabilidad sobre lo que un cuerpo humano ejecuta debe poder rastrearse a una decisión humana."

El ecosistema aplica esta disciplina con rigor en su propio dominio: P2 y P3 exigen que toda transición de estado emita un evento con razón, que "razones" sea NOT NULL, y que el historial permanezca. La trazabilidad no es un valor abstracto en BREY — es un mecanismo implementado. Pero lo está para los eventos del usuario, no para las decisiones editoriales.

De los seis datos, cero tienen campo en el modelo. El único dato de trazabilidad que el ecosistema registra —la versión de catálogo— responde "el catálogo cambió", no "esta persona decidió esto por esta razón". P14 se cumple hoy en el acto y es indemostrable después.

El contraste que hace visible la brecha

El ecosistema ya tiene un sistema de trazabilidad completo y funcionando — para el otro lado del producto.

El ecosistema sabe hacer esto

El campo origen de los eventos distingue seis productores de decisión —motor_bps, progression_engine, recovery_engine, workout_generator, usuario, coach— precisamente para saber quién decidió cada cosa. La capacidad existe, está implementada y se aplica a las decisiones automáticas. Las decisiones humanas, que son las que P14 declara más importantes, son las únicas sin ese registro.

El ADR es el único registro editorial que funciona

Todas las trazabilidades que sí existen para decisiones humanas pasan por un ADR: registra la razón, las alternativas consideradas y las consecuencias. Es el mecanismo que el ecosistema ya usa y el que este handbook adopta como modelo — con una limitación evidente: un ADR por cada asignación de patrón de cada ejercicio no escala a 100, y mucho menos a 1000 entradas. Ver módulo 17.
