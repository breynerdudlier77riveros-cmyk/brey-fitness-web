Módulo 13 · Sistema y gobernanza

API Interna

Los contratos de los 9 casos de uso (02) en pseudocódigo conceptual — sin código real, sin tipos de ningún lenguaje — más los contratos de repositorio y el catálogo de eventos de dominio prometido en 01.

Convención de los contratos

Cada caso de uso se especifica como: entrada, precondiciones, salida, errores posibles, postcondiciones y eventos que emite. Esto es lo que un equipo de implementación traduce directamente a funciones — este documento no elige lenguaje ni framework.

Contratos de casos de uso

UC-05 · RegistrarMedición
CASO DE USO: RegistrarMedición
ENTRADA: clienteId, fecha, valores (subconjunto del catálogo de 03), fotografía (opcional)
PRECONDICIONES:
  - el Cliente existe y no está en estado Eliminado
  - fecha no es futura
  - todos los valores presentes pasan su validación individual (03)
SALIDA: Medición nueva, estado = Vigente
ERRORES POSIBLES:
  - CLIENTE_NO_ENCONTRADO
  - CLIENTE_ELIMINADO
  - FECHA_FUTURA
  - VALOR_FUERA_DE_RANGO_FISICO (03, "valor imposible")
POSTCONDICIONES:
  - la Medición queda persistida y visible en el historial (05)
EVENTOS EMITIDOS: medicion_registrada
UC-06 · CorregirMedición
CASO DE USO: CorregirMedición
ENTRADA: medicionId (la que se corrige), nuevos valores, fecha (opcional, si también se corrige)
PRECONDICIONES:
  - la Medición referenciada existe y está Vigente
SALIDA: Medición original → Anulada; Medición nueva → Vigente
ERRORES POSIBLES:
  - MEDICION_NO_ENCONTRADA
  - MEDICION_YA_ANULADA (no se puede corregir una corrección directamente sin pasar por la vigente actual)
POSTCONDICIONES:
  - ambas Mediciones (anulada y nueva) quedan en el historial completo (05, IN-D1)
EVENTOS EMITIDOS: medicion_corregida
UC-07 · CrearEnlacePúblico
CASO DE USO: CrearEnlacePúblico
ENTRADA: clienteId
PRECONDICIONES:
  - el Cliente existe
SALIDA: EnlacePúblico nuevo, estado = Activo, token aleatorio (10)
ERRORES POSIBLES:
  - CLIENTE_NO_ENCONTRADO
POSTCONDICIONES:
  - si existía un EnlacePúblico Activo previo para el mismo Cliente, este pasa a Revocado (09-IN-1)
EVENTOS EMITIDOS: enlace_creado, enlace_revocado (si aplica el reemplazo automático)
UC-08 · RevocarEnlacePúblico
CASO DE USO: RevocarEnlacePúblico
ENTRADA: enlaceId
PRECONDICIONES:
  - el EnlacePúblico existe y está Activo
SALIDA: EnlacePúblico → Revocado
ERRORES POSIBLES:
  - ENLACE_NO_ENCONTRADO
  - ENLACE_YA_REVOCADO
POSTCONDICIONES:
  - el token deja de resolver, permanentemente (IN-D4, 02)
EVENTOS EMITIDOS: enlace_revocado
UC-09 · VisualizarReportePúblico
CASO DE USO: VisualizarReportePúblico
ENTRADA: token
PRECONDICIONES: ninguna — es el único caso de uso invocable sin autenticación (08)
SALIDA: Reporte computado (04) del Cliente dueño del token
ERRORES POSIBLES:
  - TOKEN_INVALIDO (no existe)
  - TOKEN_REVOCADO (existió, ya no es válido)
POSTCONDICIONES: ninguna mutación — es de solo lectura
EVENTOS EMITIDOS: ninguno de negocio; el acceso se audita a nivel de infraestructura (08)

Los cuatro casos de uso restantes (CrearCliente, EditarCliente, ArchivarCliente, EliminarClientePermanentemente) siguen el mismo patrón de contrato — se listan de forma resumida en la matriz siguiente en vez de repetir el bloque completo para cada uno.

Contratos de repositorio

RepositorioOperaciones conceptuales
RepositorioClienteobtenerPorId, listarPorEntrenador(paginado), guardar, cambiarEstado
RepositorioMedicionobtenerPorId, listarVigentesPorCliente(ordenado por fecha), guardar, anular
RepositorioEnlacePublicoobtenerPorToken, obtenerActivoPorCliente, guardar, revocar

Cada repositorio opera sobre un único tipo de agregado (02) — ninguno hace join de conveniencia entre agregados; componer datos de más de un agregado (ej. el Reporte, 04) es responsabilidad de la capa de aplicación, no del repositorio.
