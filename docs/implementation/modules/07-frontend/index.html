Módulo 07 · Construcción

Frontend

Solo el BCS tiene un handbook de diseño hoy. Los motores (Motor BPS, Progression Engine) no tienen superficie de UI propia — su única salida visible es a través de datos que el Core Product ya muestra (calendario, historial). Este módulo lo declara explícitamente en vez de asumir un trabajo de frontend que no está especificado.

Gap declarado — sin superficie de UI para Motor BPS/Progression Engine

No es un olvido de este handbook — es un vacío real en la documentación existente

A diferencia del BCS, ni Motor BPS Handbook ni Progression Engine Handbook tienen un "Design System Handbook" equivalente. Su salida (una nueva semana de entrenamiento, un cambio de nivel, una señal de estancamiento) necesitará representarse visualmente en algún momento — pero ese diseño no existe todavía en ningún documento. Este handbook no lo inventa (no le corresponde) — lo declara como bloqueante explícito para cualquier trabajo de frontend de esos dos motores, y lo registra en el Roadmap (03, Fase 4) como huérfano hasta que exista su propio handbook de diseño.

Mientras tanto, el frontend real de Motor BPS/Progression Engine se limita a lo que el Core Product ya renderiza: el calendario y el historial de entrenamientos existentes consumen la prescripción que estos motores producirán — sin superficie nueva, reutilizando componentes ya implementados.

Regla de reutilización

Ningún componente nuevo se construye sin verificar primero si ya existe un equivalente en src/components/brand/ (Engineering Handbook, 03) — la disciplina que el propio BCS Design System Handbook ya demostró (7 componentes nuevos sobre 18 reutilizados) es la misma que gobierna cualquier frontend futuro.
