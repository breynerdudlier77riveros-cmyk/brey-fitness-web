Unit Testing

Todo lo que puede probarse sin base de datos, sin red y sin reloj — el nivel de mayor prioridad porque no requiere ningún entorno además del propio código.

Paridad CHECK ↔ validación — el caso ya especificado

Regla ya establecida — Engineering Handbook, 10

Todo CHECK de rango físico (Database Handbook, 07) debe tener su contraparte de test en la validación de aplicación — ambas capas deben rechazar exactamente los mismos valores inválidos, nunca divergir. Un test de unit de esta paridad construye el valor límite exacto (ej. peso_kg = 20, el borde del CHECK > 20) y verifica que el validador de aplicación lo rechaza igual que lo haría la base de datos.

Qué nunca se prueba en unit

  • Cualquier cosa que requiera una fila real de profiles, workouts o cualquier otra tabla — eso es integration (02, 09).
  • Un flujo que invoque más de un motor en secuencia (ej. Motor BPS orquestando Recovery + Progression + Generator) — cada motor se prueba aislado en unit; la orquestación completa es integration o e2e (06).
