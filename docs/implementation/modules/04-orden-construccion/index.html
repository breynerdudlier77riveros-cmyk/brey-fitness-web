Orden exacto de despliegue

  1. Migraciones de base de datos (siempre antes que el código que las asume — nunca simultáneo, 05).
  2. Backend (repositorios, motores) — puede desplegarse sin que el frontend nuevo esté activo, porque no hay ruta que lo exponga todavía.
  3. Frontend — solo tras confirmar que el backend que consume responde correctamente en el entorno de destino.
  4. Activación de la ruta pública (para el BCS: generación de EnlacesPúblicos) — el último paso, porque expone la feature a un usuario final real.

Orden exacto de validación

  1. Validación de esquema (¿la migración aplicó sin error, RLS activo?) — automatizable, primer gate.
  2. Validación de contrato (¿el repositorio devuelve la forma exacta del DTO especificado?) — Unit testing (10).
  3. Validación de integración (¿el motor invocado produce la Decisión esperada dado un caso conocido?) — Integration testing (10).
  4. Validación end-to-end (¿el flujo completo de usuario funciona?) — la última, la más costosa, nunca la primera línea de defensa.
