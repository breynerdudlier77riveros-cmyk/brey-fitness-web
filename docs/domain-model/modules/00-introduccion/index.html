Módulo 00 · Fundamentos

Introducción

El lenguaje oficial del negocio de BREY. Define entidades, relaciones, agregados, eventos, ownership e invariantes para todo el ecosistema — la fuente única de verdad de qué existe, qué no existe, y quién es dueño de qué.

Autoridad: handbook > código Orquesta el lenguaje de 7 handbooks — no reescribe ninguno Sin código, sin SQL, sin TypeScript, sin APIs

Propósito

Los siete documentos existentes especifican, cada uno, el comportamiento de una parte del sistema. Ninguno responde de forma unificada y transversal a las preguntas más básicas del dominio: ¿cuáles son todas las entidades del ecosistema? ¿Qué conoce cada una? ¿Qué no conoce? ¿Quién es dueño de qué? ¿Qué tiene identidad propia y qué es solo un valor? Este documento responde esas preguntas una sola vez, para todo BREY.

Alcance

  • El catálogo completo de entidades, objetos de valor y agregados del ecosistema.
  • El lenguaje ubicuo — los términos oficiales, sus sinónimos permitidos y sus términos prohibidos.
  • Las relaciones, cardinalidades y máquinas de estado de cada entidad.
  • Los invariantes que ninguna implementación futura puede violar.
  • El mapeo conceptual de cada entidad a su forma de persistencia esperada — sin especificar esa persistencia.

Regla de prioridad documental

Prioridad de este documento

Si una implementación futura contradice este handbook, este handbook tiene prioridad. Frente a los siete documentos anteriores, este handbook no tiene autoridad para redefinir una regla de negocio ya decidida — solo para nombrar, clasificar y relacionar lo que esos documentos ya establecieron. En caso de conflicto real entre este documento y un handbook de dominio anterior, el handbook de dominio gana en su propio terreno (reglas de negocio); este documento gana en el suyo (nombres, identidad, ownership, relaciones).

Corrección Sprint 0 — rango frente a Architecture Review e Implementation Handbook: este documento se subordina a ambos. Frente a la Architecture Review v1.0, sus hallazgos 🔴/🟠 gobiernan cualquier ajuste de este handbook. Frente al Implementation Handbook, escrito antes, este documento nunca reordena la secuencia de construcción que aquel ya fijó — solo nombra y relaciona lo que se construye, nunca cuándo.

Cómo leer el documento

Cada entidad, objeto de valor o término se presenta con su handbook de origen citado explícitamente — nunca se afirma algo sobre una entidad sin poder señalar de dónde viene esa afirmación. Se reutiliza el sistema de tres etiquetas ya establecido:

implementado especificado futuro

Y se añade un cuarto uso propio de este documento: cuando una entidad tiene identidad conceptual clara pero ningún handbook anterior definió su persistencia, se declara explícitamente como tal (13) — nunca se inventa una tabla o estructura no autorizada por ningún documento previo.
