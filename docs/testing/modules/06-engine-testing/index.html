Progression Engine

Matriz Regla → Test (por categoría)

El catálogo completo de 39 reglas (Progression Engine Handbook, 07) ya incluye, para cada una, "Ejemplo válido" y "Ejemplo inválido" — esos dos campos son, literalmente, el caso de test positivo y negativo. Esta matriz traza por categoría, no fila por fila las 39 (esa tabla ya existe en su handbook de origen); replicarla aquí sería transcripción, no especificación de testing.

CategoríaReglasPatrón de test
MicroprogresiónPE-001–012Una ventana con la señal exacta que activa la regla (ej. RPE reportado bajo umbral) → verificar la Prescripción resultante; una ventana sin esa señal → verificar que no cambia
MacroprogresiónPE-013–018Ventana de ≥4 apariciones en el patrón de avance/sostiene/retrocede → verificar la Decisión; PE-016 verifica que la salida es una recomendación, nunca una escritura directa de nivel_actual (05, ownership)
AutorregulaciónPE-019–026Veredicto de Recovery con procede: false → verificar que ninguna otra regla del catálogo se evalúa ese ciclo (PE-026)
EstancamientoPE-027–032Exactamente 3 apariciones sin avance consecutivas → verificar transición a "candidato"; una cuarta con avance → verificar reinicio
DeloadPE-033–039Veredicto subtipo: "programada" vs. "reactiva" → verificar el multiplicador de volumen correspondiente
PE-012 — caso de desempate sin definición operacional (AR-008, no resuelto aquí)

La Architecture Review ya identificó que "menor magnitud de cambio" no está operacionalizado entre unidades heterogéneas (kg vs. repeticiones). Este documento no resuelve esa ambigüedad — especifica que cualquier test de PE-012 debe fijar explícitamente qué criterio de comparación usa la implementación bajo prueba, y marcarlo bloqueado hasta que AR-008 se resuelva en Progression Engine Handbook, para no congelar en el test una interpretación que el propio handbook de origen todavía no decidió.
