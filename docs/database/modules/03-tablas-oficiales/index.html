systemspersistente

Catálogo-espejo de Sistemas comerciales

Descripción
Catálogo liviano de los Sistemas vendibles (Calistenia, Hipertrofia, Híbrido, Fuerza, Elite) — el contenido rico (ontología, plantillas) vive en código versionado, no aquí (Architecture Handbook, ADR-009).
Owner (bounded context)
Core Training
Aggregate root
Ninguno — es catálogo, no dato de usuario ni historial
Quién escribe
Nadie por RLS de aplicación — gestión vía dashboard/service role únicamente
Quién lee
Cualquiera, incluso Anonymous (lectura pública)
Quién nunca escribe
Ningún motor ni Server Action de usuario final
Quién nunca lee
No aplica — lectura sin restricción
profilespersistente

Perfil del Usuario

Descripción
Fila 1:1 con auth.users, 20 columnas — identidad, datos físicos, preferencias de entrenamiento, y los dos punteros de estado del Motor BPS (sistema_actual, nivel_actual).
Owner (bounded context)
Identity
Aggregate root
Usuario (Domain Model Handbook, 08)
Quién escribe
El propio Usuario, sus campos generales; el proceso de Diagnóstico/Motor BPS, exclusivamente sistema_actual/nivel_actual (Domain Model Handbook, DX-04)
Quién lee
El propio Usuario; Motor BPS, Progression Engine, Workout Generator (lectura fresca cada ciclo)
Quién nunca escribe
Ningún otro Usuario; BCS (frontera de contexto, 02)
Quién nunca lee
Cualquier actor Anonymous; cualquier Entrenador vía el panel del BCS
diagnosespersistente

Resultado de Diagnóstico

Descripción
Un Diagnóstico completado — Sistema recomendado, Nivel de entrada, razones. Un Usuario puede tener múltiples a lo largo del tiempo; retomar siempre crea uno nuevo (Domain Model Handbook, DM-ADR-07).
Owner (bounded context)
Diagnostics
Aggregate root
Diagnóstico (Domain Model Handbook, 08)
Quién escribe
El proceso de Diagnóstico — una sola vez, en su creación
Quién lee
El propio Usuario; Motor BPS (lectura del resultado vigente para activación)
Quién nunca escribe
Nadie tras la creación — ni el propio Usuario, ni ningún motor (inmutable, P3)
Quién nunca lee
Progression Engine, Recovery Engine (no es su entrada — solo Motor BPS la consulta)
workoutspersistente

Sesión de entrenamiento planificada

Descripción
Una sesión instanciada por el Workout Generator — sus Slots y Prescripciones vigentes viven dentro, como jsonb (04). Siempre el plan, nunca la ejecución.
Owner (bounded context)
Core Training
Aggregate root
Workout (Domain Model Handbook, 08; DM-ADR-02)
Quién escribe
El Workout Generator, exclusivamente — el estado transiciona por el propio ciclo del Motor BPS
Quién lee
El propio Usuario; Progression Engine (lectura, nunca escritura, para evaluar el ciclo)
Quién nunca escribe
El Usuario directamente; Progression Engine; Recovery Engine; cualquier Client Component
Quién nunca lee
Cualquier otro Usuario; cualquier actor del BCS
workout_logspersistente

Sesión de entrenamiento ejecutada

Descripción
Lo que un Usuario realmente ejecutó — Series con carga/reps/esfuerzo reales, vía el Workout Player. Puede existir sin workout_id (sesión ad-hoc).
Owner (bounded context)
Core Training
Aggregate root
WorkoutLog — separado de Workout (Domain Model Handbook, DM-ADR-02)
Quién escribe
El Usuario, a través del Workout Player — una sola escritura por sesión, al cierre (I-W3)
Quién lee
El propio Usuario; Progression Engine (ventana de historial, su única fuente real)
Quién nunca escribe
Nadie tras el cierre de sesión — ni el propio Usuario (corrección = registro nuevo, no edición)
Quién nunca lee
Cualquier otro Usuario; cualquier actor del BCS
progression_eventspersistente

Historial append-only de decisiones de motor

Descripción
El único registro de auditoría transversal del ecosistema (excluyendo BCS) — cada fila es una decisión ya tomada por Motor BPS, Progression Engine, Recovery Engine, Workout Generator, o un override del propio Usuario (08).
Owner (bounded context)
Compartida — partición lógica vía origen (ENG-ADR-03)
Aggregate root
EventoProgresión (Domain Model Handbook, 08) — sin jerarquía entre eventos
Quién escribe
El motor que origina cada tipo de evento — cada uno escribe solo los tipos de su origen (08)
Quién lee
El propio Usuario (timeline); Motor BPS (replay de estado, IN-5); Progression Engine (evaluación del ciclo siguiente); Observabilidad
Quién nunca escribe
Cualquier UPDATE o DELETE, de cualquier actor — append-only sin excepción (DM-ADR-06)
Quién nunca lee
Cualquier actor del BCS; cualquier actor Anonymous
bcs_clientespersistente

Cliente del Entrenador (BCS)

Descripción
Persona presencial medida por un Entrenador — standalone, sin relación de dominio con Usuario (Domain Model Handbook, IN-31). Contiene solo sus propios datos identificativos y estado.
Owner (bounded context)
Body Composition
Aggregate root
Cliente (BCS Handbook, BCS-ADR-01)
Quién escribe
El Entrenador que lo creó, vía el panel del BCS
Quién lee
El Entrenador dueño únicamente
Quién nunca escribe
El propio Cliente (nunca se autentica, BCS Handbook, 00); cualquier otro Entrenador
Quién nunca lee
Motor BPS, Progression Engine, Recovery Engine, Workout Generator — ningún motor de Core Training conoce esta tabla (02)
bcs_medicionespersistente

Medición de composición corporal

Descripción
Captura puntual de hasta 25 variables (04), con fecha. La tabla más ancha del ecosistema — 28 columnas en total (25 variables + id, cliente_id, estado).
Owner (bounded context)
Body Composition
Aggregate root
Medición — independiente de Cliente, solo lo referencia (BCS Handbook, BCS-ADR-01)
Quién escribe
El Entrenador dueño del Cliente referenciado, vía el panel del BCS
Quién lee
El Entrenador dueño; el Cliente, indirectamente, a través de un bcs_enlaces_publicos válido
Quién nunca escribe
Cualquier UPDATE en sitio de una fila vigente — la corrección siempre anula + crea (BCS-ADR-03, IN-D1)
Quién nunca lee
Cualquier otro Entrenador; cualquier motor de Core Training
bcs_enlaces_publicospersistente

Token de acceso público al Reporte

Descripción
Token de solo lectura y anónimo al Reporte computado de un Cliente — nunca almacena el Reporte mismo, solo el token y su estado.
Owner (bounded context)
Body Composition / Reporting
Aggregate root
EnlacePúblico — independiente de Cliente (BCS Handbook, BCS-ADR-01)
Quién escribe
El Entrenador dueño del Cliente referenciado, vía el panel del BCS
Quién lee
El Entrenador dueño (gestión); cualquier portador del token, solo para resolver a un Reporte de solo lectura si estado = activo
Quién nunca escribe
Cualquier actor Anonymous; el propio Cliente
Quién nunca lee
Cualquier otro Entrenador; ningún motor de Core Training
