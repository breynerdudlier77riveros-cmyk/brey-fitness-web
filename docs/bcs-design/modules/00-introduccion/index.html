Módulo 00 · Fundamentos

Introducción

El sistema de diseño completo de la interfaz del Body Composition System (BCS): cada decisión visual, de layout, de componente y de comportamiento, especificada para que ningún desarrollador tenga que decidir nada por su cuenta. Si una implementación futura contradice este documento, el documento tiene prioridad.

Autoridad: handbook > código Extiende el sistema de diseño real de BREY, no lo reemplaza Sin código, sin CSS, sin componentes React

Objetivo

Especificar la interfaz completa del BCS (dashboard del entrenador y vista pública del cliente) con el mismo rigor de dominio que el BCS Handbook (arquitectura de datos) ya aplicó al negocio. Este documento resuelve la pregunta "¿cómo se ve y se siente?" con la misma precisión con la que aquel resolvió "¿qué hace?".

Hallazgo de partida — este sistema ya existe, parcialmente

Grounding real, no inventado

Antes de escribir una sola regla, se auditó el código real de BREY (src/app/globals.css, src/components/brand/*.tsx). BREY ya tiene: una paleta de marca fijada (fondo #020617, acento #f97316), una librería de 18 componentes reutilizables (Card, Button, Tabs, Badge, Progress, Dialog, Accordion, Tooltip, Input, Select y más), tipografía Inter, y un ritmo de movimiento propio (300–500ms, con prefers-reduced-motion centralizado). También existen, citadas en comentarios de código pero nunca formalizadas como documento, dos leyes de una "Constitución de Diseño" no escrita: Ley 2 — "un color, un significado" — y Ley 7 — "primitivas antes que páginas, nunca SVG inline". Este handbook no inventa un sistema paralelo: extiende el real, formaliza esas dos leyes por primera vez, y las hace cumplir sin excepción en todo el dominio de composición corporal. Decisión formal en BCSD-ADR-01 (20).

Filosofía

Se desarrolla en profundidad en el módulo 01. En una frase: cada pantalla del BCS debe sentirse como una extensión natural de BREY, nunca como una herramienta distinta pegada al costado — y debe comunicar datos de salud con la misma seriedad clínica-sin-ser-clínica que el BCS Handbook exige en su contenido.

Qué problema resuelve este documento

  • Elimina la ambigüedad visual: ningún desarrollador decide "qué color usar aquí" o "cuánto espacio dejar" — ya está decidido.
  • Da a cada uno de los 25 datos del catálogo del BCS Handbook (03) una representación visual definida: tipo de gráfico, color, escala, unidad.
  • Especifica dos experiencias completas (dashboard del entrenador, vista pública del cliente) a nivel de pantalla, no solo de componente suelto.
  • Fija el comportamiento del sistema ante datos incompletos, errores, y volúmenes grandes de historial — sin dejarlo a la improvisación.
