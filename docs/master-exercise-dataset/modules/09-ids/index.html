Sección 09 · Estabilidad

Identificadores

El id es el único valor del dataset que no significa nada. Esa es exactamente su virtud: nada de lo que se descubra sobre un ejercicio puede obligar a cambiarlo.

Formato

PropiedadDecisión
FormaEX-NNNN
PrefijoEX- literal, siempre en mayúsculas
DígitosExactamente 4, con ceros a la izquierda
RangoEX-0001 … EX-9999
Capacidad9 999 ejercicios — 45 veces el objetivo de 220
Primer IDEX-0001 · el 0000 no se usa
LongitudSiempre 7 caracteres — ordenable como texto sin sorpresas
Por qué 4 dígitos fijos y no un contador libre

La longitud constante hace que el orden alfabético coincida con el orden numérico: EX-0009 precede a EX-0010 tanto para una persona como para cualquier ordenación por texto. Con ancho variable, EX-10 se ordenaría antes que EX-9 y el orden determinista de la sección 05 dejaría de ser trivial.

IX-4 · Los huecos son normales y deseables

Si EX-0087 se crea en borrador y se abandona, ese número no vuelve al contador. El dataset tendrá un hueco permanente, y está bien: el ID solo tiene que ser único y estable, no denso. Rellenar huecos exigiría verificar que el número abandonado nunca salió a ningún sitio — una comprobación imposible de garantizar, a cambio de un beneficio nulo.

IX-7 · Nada de IDs con significado

Un esquema como EX-PH-0042 —con el patrón embebido— parece útil hasta la primera reclasificación: entonces el ID contradice a la entrada, y las dos únicas salidas son mentir o romper la inmutabilidad. Por eso el ID no codifica absolutamente nada. Todo lo que se quiera saber de un ejercicio se consulta en sus campos.

Rangos

RangoUsoEstado
EX-0000No se usa — evita ambigüedad con «sin valor»Prohibido
EX-0001 … EX-8999Asignación secuencial ordinariaActivo
EX-9000 … EX-9899Reservado — sin uso definido en v1.0Reservado
EX-9900 … EX-9999Reservado para datos de ejemplo, pruebas y documentaciónReservado
El rango EX-99xx nunca llega a producción

Se reserva para que un ejemplo de documentación o un dato de prueba tenga un ID con forma válida sin poder colisionar jamás con una entrada real. Cualquier consumidor puede rechazar de plano un ID en este rango. Los ejemplos de este documento que usan EX-0042 son ilustrativos y no constituyen entradas del dataset.

El contador

PropiedadDecisión
Dónde viveEs derivado: el máximo id del índice maestro
Por qué derivadoUn contador almacenado aparte puede desincronizarse; uno derivado no puede
Cómo se leeMáximo del índice, incluyendo entradas en cualquier estado
ConcurrenciaDos altas simultáneas producen colisión — se resuelve en la revisión del cambio, antes de integrarlo
VerificaciónInvariante ARQ-1: unicidad global, comprobada en cada publicación
La colisión concurrente es visible, no silenciosa

Si dos personas crean una entrada a la vez, ambas proponen el mismo ID. Como el dataset vive en control de versiones, la segunda integración muestra el conflicto de forma explícita: se reasigna el ID de una de las dos y se integra. Es la propiedad que hace innecesario cualquier mecanismo de reserva de IDs — la del riesgo IX-6.

ID-5 · Toda referencia interna usa id

Ningún campo del modelo referencia a otro ejercicio por slug ni por nombre. Es la regla que hace que el grafo de relaciones sea validable de forma mecánica: comprobar que no hay referencias colgantes es comparar una lista de IDs contra el índice.
