Convenciones HTTP

Cuándo usar cada método, qué status code corresponde a cada resultado, y qué headers son obligatorios. Notación transporte-agnóstica (01, API-ADR-01) — aplica igual a una Server Action, un Route Handler o una futura API pública.

Métodos — cuándo usar cada uno

MétodoCuándoIdempotenteEjemplo real (07)
GETToda Query — lectura sin efecto secundario de dominio (puede registrar auditoría de acceso, 14)Sí, por definiciónGET /bcs/clientes/{id}
POSTCrear un recurso nuevo, o disparar una acción de dominio que no es ni creación ni actualización pura (revocar, archivar, evaluar)Depende de la operación — ver 11POST /bcs/clientes, POST /bcs/enlaces/{id}/revocar
PATCHActualización parcial de un subconjunto de campos de un recurso ya existenteSí — mismo body, mismo resultado, salvo la excepción documentada abajoPATCH /perfil, PATCH /bcs/clientes/{id}
PUTReemplazo completo de un recurso — ningún endpoint de este catálogo lo usa hoySí, por definiciónNinguno — ver nota abajo
DELETEEliminación irreversible de un recurso — reservado a los casos donde el dominio define explícitamente una eliminación permanente, distinta de un archivado reversibleSíDELETE /bcs/clientes/{id} (UC-04, irreversible)
Por qué PUT no aparece en el catálogo

El dominio de BREY no tiene una operación de "reemplazo completo" real: toda corrección de un registro histórico (Medición, Diagnóstico) se modela como anular + crear (11, FT-09), nunca como sobrescritura total del recurso — y toda edición de un recurso vivo (Perfil, Cliente) es intencionalmente parcial (PATCH). Se documenta PUT aquí por completitud de la convención HTTP, no porque el catálogo (07) lo necesite. Si un futuro caso de uso lo requiriera, debe declarar explícitamente por qué PATCH no basta antes de introducirlo.

Headers

HeaderRegla
Content-Typeapplication/json en toda request/response con body — sin excepción salvo la subida de fotografía de Medición (multipart, directo a Storage, fuera de este contrato)
Cache-Controlpublic, max-age=… únicamente en GET /sistemas (catálogo, lectura pública) — no-store en cualquier endpoint que devuelva datos de un Usuario, Cliente o Medición (dato personal, nunca cacheado por un intermediario)
AuthorizationNo aplica — la sesión viaja por cookie httpOnly, no por header Bearer (03)
