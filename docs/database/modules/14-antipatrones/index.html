Módulo 14 · Gobernanza

Anti-patrones

18 formas reales de romper este modelo — cada una ya evaluada y descartada por algún handbook, nunca hipotética.

18 anti-patrones
#Anti-patrónPor qué está prohibidoEvidencia
ANP-01Duplicar el estado en dos lugares (ej. una tabla recovery_states separada, cuando el evento ya lo captura)Dos fuentes de verdad para el mismo hecho divergen con el tiempo — el estado siempre debe ser un puntero derivado de un único log de eventosDM-ADR-04 — evaluado y descartado
ANP-02Guardar Programa, Bloque, Mesociclo o Microciclo como fila propia con idSon posicionales, no entidades con identidad — persistirlos como fila les daría una existencia independiente que el dominio ya decidió que no tienenDomain Model Handbook, 13; 03 de este documento
ANP-03Dos procesos escribiendo la misma columna sin ownership único (ej. Usuario y Motor BPS escribiendo nivel_actual por caminos distintos)Rompe SSoT — sin un propietario único, dos escritores concurrentes producen estados contradictorios sin que ninguno sea "el correcto"01 (SSoT); 09 (brecha real conocida en profiles, sin resolver — no repetir el mismo error en tablas nuevas)
ANP-04Saltar la capa de repositorios — acceso directo a Supabase desde un Server/Client ComponentLos repositorios son la única capa que toca la base de datos — saltarlos rompe la coerción centralizada y la frontera de RLS/ownership documentadaArchitecture Handbook, 11
ANP-05Escribir una mutación de dominio desde un Client ComponentToda escritura de dominio pasa por una Server Action — un Client Component que escribe directo expone lógica de negocio al cliente y evade la revisión de RLS del lado servidorEngineering Handbook, 04
ANP-06Editar en sitio un WorkoutLog cerrado, una bcs_medicion vigente, o cualquier progression_eventRompe la inmutabilidad de historial (P3/FT-09) — la única forma válida de "corregir" es un registro nuevo09 (RLS sin UPDATE/DELETE en estas tablas, a propósito)
ANP-07Usar CREATE TYPE ... AS ENUM nativo de Postgres en vez de text + CHECKALTER TYPE ... ADD VALUE tiene restricciones históricas de transacción que CHECK no tiene — la migración de agregar un valor debe ser simple y simétrica con TypeScriptENG-ADR-02
ANP-08Crear una tabla de eventos nueva por cada motor (motor_bps_events, recovery_engine_events, etc.)Fragmenta el timeline cronológico de un Usuario en múltiples tablas, forzando un UNION costoso para cualquier vista agregadaENG-ADR-03
ANP-09Anidar Mediciones y EnlacesPúblicos dentro del agregado Cliente (una sola tabla con arrays internos)Obliga a cargar potencialmente cientos de registros cada vez que se toca cualquier dato del Cliente, y el agregado crece sin límite superiorBCS-ADR-01
ANP-10Dejar que Progression Engine o Recovery Engine hagan su propio I/O contra la base de datosAmbos son funciones puras por diseño — reciben su historial ya leído como argumento; hacer su propio I/O rompe el determinismo y la posibilidad de test sin mocks de base de datosProgression Engine Handbook, IN-P1; Architecture Handbook, 06
ANP-11Persistir una SeñalFatiga cruda en cualquier tabla accesible fuera de Recovery EngineNingún otro contexto debe ver la señal cruda — solo el Veredicto ya resuelto (P8, IN-21)Domain Model Handbook, IN-21
ANP-12Crear una tabla para persistir el Reporte del BCSEl Reporte nunca puede quedar desactualizado respecto a una corrección de Medición si siempre se computa on-demand — persistirlo introduce el riesgo de divergencia silenciosaBCS-IN-D3; DM-ADR-08
ANP-13Confiar en el proxy (proxy.ts) como única barrera de seguridad de una tabla, en vez de RLSUn bug en el proxy, o un acceso directo a la API de Supabase sin pasar por Next.js, expondría los datos sin ninguna otra barreraENG-ADR-04
ANP-14Cambiar la forma de un campo jsonb ya publicado sin discriminador de versiónRompe silenciosamente a cualquier mapper que espere la forma vieja — la evolución de jsonb siempre es aditiva con campo vArchitecture Handbook, 10; 11 de este documento
ANP-15Crear un índice especulativo antes de que exista una consulta real que lo necesiteUn índice sin una consulta real es costo de escritura sin beneficio de lectura — la misma disciplina de "sin abstracción sin caso de uso" aplicada a datosENG-ADR-01 (mismo principio); 06 de este documento
ANP-16Fusionar los 10 eventos del BCS dentro de progression_eventsForzaría a BCS a depender del esquema de Progression — la dependencia exacta que el bounded context de BCS prohíbe (standalone en v1)08 de este documento; BCS Handbook, 00
ANP-17Mapear o traducir nivel_actual entre dos Sistemas distintos (ej. asumir que "Skills" de Calistenia equivale a algo en Hipertrofia)Los niveles son configuraciones internas de cada Sistema, no una escala universal — una tabla de equivalencias sería fisiología inventadaMBPS-ADR-06
ANP-18Coercionar una columna numeric (Number(row.x)) fuera de la capa de mappersPostgREST serializa numeric como string — numOrNull() es el único punto de coerción del sistema; un bug real de este tipo ya ocurrió (una suma que concatenaba strings en el agregado de progreso)Architecture Handbook, 10, ADR-007
