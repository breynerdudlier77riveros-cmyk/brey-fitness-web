Módulo 14 · Gobernanza

Observabilidad

Qué se registra hoy, con qué convención real, y qué no existe todavía — sin inventar un request ID donde ningún handbook lo pide.

Sin request ID, trace ID ni correlation ID — gap confirmado, no se inventa aquí

El Observability Handbook (Engineering, 11) es explícito: "sin distributed tracing... un trace ID por request añadiría complejidad sin un problema real que resolver todavía". Este documento no formaliza una convención de propagación de identificador de request porque ningún handbook la especifica — inventarla violaría la restricción de este encargo. Se registra como pregunta abierta (AP-05, 16).

Logs — convención real

Todo endpoint de este catálogo que registre un log de advertencia o error sigue el formato ya real: console.warn(`[contexto] mensaje`) para condiciones degradadas no fatales, console.error(`[contexto] mensaje`) para fallos de servicio externo. El prefijo entre corchetes identifica el origen ([lead], [contacto], y por extensión [bcs], [motor-bps] para los endpoints de este catálogo) — ningún log nuevo se escribe sin ese prefijo (Observability Handbook, Engineering 11).

Eventos como mecanismo de observabilidad

progression_events con origen en motor_bps/progression_engine/recovery_engine es, además de historial de negocio, la fuente de KPIs de observabilidad ya especificados (Observability Handbook, Engineering 11) — ej. frecuencia de VENTANA_INSUFICIENTE, tasa de avanza vs. sostiene. Ningún endpoint nuevo se necesita para esto: son consultas agregadas sobre GET /motor-bps/eventos (07).

Auditoría — BCS

Toda escritura sobre bcs_clientes/bcs_mediciones/bcs_enlaces_publicos queda registrada de forma inmutable: quién, qué acción, sobre qué entidad, cuándo, valor anterior donde aplica (BCS Handbook, 08). El acceso vía EnlacePúblico se audita sin identidad — se registra que el enlace fue visitado, nunca quién lo visitó; el token nunca se registra en texto plano, solo su identificador interno.

Evento de seguridadCuándo

Sin health-check ni alerting

Confirmado por el Observability Handbook (Engineering, 11): no existe endpoint de salud ni alerting configurado. Ver 07 (gap documentado) y 16 (AP-06).
