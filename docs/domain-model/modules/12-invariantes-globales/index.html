Módulo 12 · Comportamiento

Invariantes Globales

Treinta reglas que nunca pueden violarse, clasificadas por severidad. Cada una cita su fuente — ninguna es nueva, todas ya estaban implícitas o explícitas en los módulos 01–11 o en un handbook anterior.

Corrección respecto a un ejemplo del encargo original

El encargo de este handbook incluye, como ejemplo ilustrativo, "Nunca existe un Reporte sin Medición". El BCS Handbook (04) ya especifica explícitamente lo contrario: un Cliente sin ninguna Medición registrada SÍ tiene Reporte — un estado vacío explícito ("Sin mediciones registradas"), nunca un error. Adoptar la regla del ejemplo literalmente contradiría un handbook ya cerrado, lo cual el propio encargo prohíbe. Este módulo la reemplaza por IN-24 (un Reporte nunca se persiste independientemente de sus Mediciones fuente) y añade IN-25 (nunca existe un Reporte para un Cliente inexistente), que capturan la misma intención — "el Reporte siempre depende de su Cliente" — sin contradecir la regla del estado vacío.

Identity y Diagnóstico

IN-01
crítica

Nunca existe un Usuario sin su Perfil correspondiente — la relación es 1:1 obligatoria desde la creación (Architecture Handbook).

IN-02
crítica

Nunca existe un Diagnóstico sin el Usuario que lo origina.

IN-03
alta

Nunca existe una Respuesta fuera de un Diagnóstico — no tiene identidad ni ciclo de vida propios (DX-02).

IN-04
media

Un Diagnóstico en estado completado nunca vuelve a en curso — retomar crea un Diagnóstico nuevo (P3, 10).

IN-05
crítica

Nunca existe un Programa en estado activo sin un Diagnóstico completado previo (Motor BPS Handbook, T3–T5; 10).

IN-06
crítica

Nunca existe un Programa sin un Usuario con posición activa apuntando a él (profiles.sistema_actual/nivel_actual, 13).

Core Training

IN-07
crítica

Nunca existe un Bloque fuera de un Programa.

IN-08
alta

Nunca existe un Mesociclo fuera de un Bloque.

IN-09
alta

Nunca existe un Microciclo fuera de un Mesociclo.

IN-10
crítica

Nunca existe un Workout sin un Usuario propietario.

IN-11
alta

Nunca existe un Slot fuera de un Workout.

IN-12
crítica

Nunca existe un Diagnóstico en estado completado sin un ResultadoDiagnóstico asociado (10).

IN-13
alta

Nunca existe una Serie fuera de un Slot ejecutado, dentro de un WorkoutLog.

IN-14
media

Un Slot nunca referencia un Ejercicio por nombre directo — solo por Patrón×Rol (P7).

IN-15
alta

Un Workout en estado completado o perdido nunca vuelve a planificado — estado final sin retorno (FT-09).

IN-16
media

nivel_actual y nivel_experiencia nunca se sincronizan ni se confunden automáticamente entre sí (ADR-003, 04).

Progresión y Recuperación

IN-17
crítica

Nunca existe una Prescripción sin el Slot que la recibe — relación 1:1 obligatoria (PR-01).

IN-18
media

RPE y RIR nunca coexisten como reporte válido dentro de la misma Serie (PE-ADR-05, VO-07/VO-08).

IN-19
crítica

Nunca existe un EventoProgresión sin el Usuario que lo origina.

IN-20
alta

Un EventoProgresión, una vez insertado, nunca se edita ni se borra — append-only (FT-09).

IN-21
crítica

Ninguna SeñalFatiga ni Dolor crudo sale de Recovery Engine hacia otro contexto — solo su EstadoRecuperación ya resuelto (P8, 09-diagrama 9).

Composición Corporal

IN-22
crítica

Nunca existe una Medición sin un Cliente válido — clienteId obligatorio en todo su ciclo de vida (BCS-IN-D5).

IN-23
alta

Una Medición vigente nunca se edita en sitio — toda corrección crea una Medición nueva y anula la anterior (BCS-IN-D1).

IN-24
media

Un Reporte nunca se persiste independientemente de sus Mediciones fuente — siempre se computa on-demand (BCS-IN-D3).

IN-25
alta

Nunca existe un Reporte para un Cliente inexistente — puede existir con cero Mediciones (estado vacío explícito), nunca sin Cliente (BCS Handbook, 04).

IN-26
crítica

Nunca existe un EnlacePúblico sin un Cliente válido.

IN-27
alta

Nunca existen dos EnlacesPúblicos en estado Activo simultáneos para el mismo Cliente (BCS Handbook, 09-IN-1).

IN-28
alta

Un EnlacePúblico revocado nunca se reactiva — compartir de nuevo siempre crea un token distinto (BCS-IN-D4).

IN-29
crítica

Un Cliente eliminado dispara revocación en cascada de todos sus EnlacesPúblicos (BCS Handbook, UC-04, 10).

IN-30
media

Un Cliente en estado Eliminado nunca retorna a Activo ni a Archivado — terminal (BCS-IN-D2).

Transversales

IN-31
crítica

Nunca existe una relación de dominio directa entre Usuario y Cliente — la identidad del Usuario autoriza la operación sobre un Cliente, nunca implica propiedad de dominio entre ambos (09-diagrama 13).
