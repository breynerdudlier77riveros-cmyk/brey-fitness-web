Módulo 08 · Ejecución

Workout Generator

El ensamblador. No decide nada nuevo: toma el Microciclo vigente (plantilla), el Perfil fresco, la prescripción del Progression Engine y el veredicto del Recovery Engine, y materializa Sesiones concretas — el momento exacto donde plantilla se convierte en instancia inmutable (P5). Si alguna pieza no alcanza, falla visible con detalle (P6).

Ensamblador, no decisor Genera la semana completa Instancia desnormalizada (P5)

Objetivo, alcance, dependencias, invariantes

Objetivo: convertir decisiones ya tomadas en filas de workouts listas para el Player. Alcance: selección/filtrado/sustitución de ejercicios (delegando reglas a 04), aplicación de multiplicadores, orden por Rol (R-4 de 03), materialización desnormalizada. Fuera de alcance: decidir prescripciones base (03/05), decidir descarga (06), estados del usuario (07). Depende de: 03, 04, 05, 06, 07. Invariantes: I-G1 nunca genera una sesión con un slot vacío o forzado fuera de reglas; I-G2 la instancia copia todo lo que necesita — jamás referencia plantillas en lectura posterior (P5); I-G3 misma entrada → misma semana generada, byte a byte (P1); I-G4 corre solo si el Motor BPS lo invoca (gates ya pasados).

Entradas y salidas

EntradaDe
Plantilla del Microciclo vigente (sesiones × slots Patrón×Rol + prescripción base de la semana del Mesociclo)Catálogo (03)
Perfil fresco: Track, duración por sesión, zonas (declaradas + temporales)Perfil / eventos (06)

Salida: N filas de workouts (una por sesión de la semana), cada una autocontenida: fecha, duración estimada, y por slot — patrón, rol, ejercicio (slug + nombre), series, reps/duración, RPE objetivo, descanso, tempo (si aplica), notas. Más el evento semana_generada con la versión de catálogo usada (P2/P3).

Pseudocódigo

FUNCIÓN generarSemana(microciclo, perfil, prescripcion, recovery):
  mult ← recovery.si ? 0.6 : 1.0              // multiplicador de descarga (06)
  rpeDelta ← recovery.si ? −1 : 0
  sesiones ← []

  PARA cada plan EN microciclo.sesiones:
    slots ← ordenarPorRol(plan.slots)            // R-4 de 03 — orden no alterable
    slots ← recortarPorTiempo(slots, perfil.duracion_sesion_min)   // ver Regla de Recorte
    resueltos ← []

    PARA cada (patron, rol) EN slots:
      ej ← KB.resolverEjercicioParaSlot(patron, rol, perfil.track, nivel, perfil.zonas, capacidades)
      SI ej es error ENTONCES RETORNAR fallo(CATALOGO_INSUFICIENTE, detalle: ej.detalle)  // I-G1, semana completa falla

      p ← prescripcion.para(patron, rol)          // base del Mesociclo + ajuste micro vigente
      resueltos.agregar({
        patron, rol,
        ejercicio: {slug: ej.slug, nombre: ej.nombre, modalidad: ej.modalidad},   // desnormalizado (I-G2)
        series: redondear(p.series · mult),
        reps: p.rango, rpe: p.rpe + rpeDelta,
        descanso: descansoPorRol(rol, bloque.enfasis),
        tempo: p.tempo ?? "controlado", notas: plan.notasPara(patron, rol)
      })

    sesiones.agregar(materializar(plan.fecha, plan.duracionEstimada, resueltos))

  EMITIR evento("semana_generada", versionCatalogo, recovery.tipo ?? "normal")
  RETORNAR sesiones

Reglas del motor

R-G1 · Semana completa, no sesión por sesión

Se genera el Microciclo entero de una vez — el usuario ve y planea su semana. Un fallo en cualquier slot aborta la semana completa con detalle (I-G1): nunca media semana silenciosamente coja.

R-G2 · Regla de Recorte por tiempo

Si la duración estimada excede duracion_sesion_min, se recorta en orden inverso de prioridad: metabolico → core-final → accesorio (nunca principal ni activacion). Si aún así no cabe, la sesión se genera marcada "excede tu tiempo declarado" — informar sobre mutilar. decisión de producto

R-G3 · Multiplicador de descarga uniforme

La descarga aplica a toda la semana por igual (0.6 volumen, −1 RPE), nunca sesión por sesión.

Trade-offs y decisiones descartadas

Semana completa vs. bajo demanda

Visibilidad total para el usuario, a cambio de que cambios a mitad de semana solo afecten lo aún no generado (P5). La sustitución en vivo del Player cubre el hueco restante.

Rellenar huecos con "el menos malo"

Descartado — violaría P6 y el filtro de seguridad. Un vacío de catálogo es trabajo editorial, no un problema a maquillar en runtime (P14).

Variedad aleatoria de ejercicios

Descartado — P1. La variedad legítima se expresa como rotación determinista definida en la plantilla.

Riesgos, deuda y extensiones

El vacío de catálogo se experimenta aquí

Aunque la causa es editorial (04), el usuario lo vive como "no puedo generar mi semana". El mensaje de producto y la cola editorial alimentada por estos errores son parte del diseño, no un extra.

Extensión — generación multi-semana

Cambio de frecuencia de invocación, no de lógica. Encaja cuando el producto quiera mostrar el Mesociclo completo por adelantado.

Preguntas abiertas

  • ¿La invalidación de una semana no ejecutada la puede pedir el usuario ("regenerar mi semana") o solo eventos del sistema (cambio de Track)? Propuesta: ambos, con evento diferenciado — sin decidir, Roadmap H2.
