Módulo 05 · Reporte

Modelo del Historial

Cómo se acumula, ordena, corrige y compara el historial ilimitado de Mediciones de un Cliente — sin borrar nunca un dato ya registrado.

Objetivo

Que el historial sea append-only en la práctica: toda corrección añade, nunca sobrescribe, preservando trazabilidad completa de qué se registró y cuándo se corrigió.

Ordenamiento y consulta

Las Mediciones se listan siempre por fecha ascendente para gráficos de tendencia (07) y descendente para el listado del panel (la más reciente primero). Solo las Mediciones en estado vigente (02) participan del historial visible — las anuladas existen en la base de datos por trazabilidad pero nunca aparecen en el Reporte ni en los gráficos.

Corrección de una Medición pasada

UC-06 CorregirMedición — nunca edición en sitio
sequenceDiagram
  participant E as Entrenador
  participant S as BCS
  E->>S: corrige Medición del 10-mar (peso mal digitado)
  S->>S: marca la Medición del 10-mar como anulada
  S->>S: crea una Medición nueva, fecha=10-mar, vigente
  S-->>E: historial actualizado — ambas existen, solo una es visible

La fecha de la Medición corregida se conserva igual a la original — lo que cambia es el estado (vigente/anulada), nunca la fecha que el corrector quiso corregir salvo que la fecha misma fuera el error a corregir, en cuyo caso la nueva Medición lleva la fecha correcta.

Comparación entre dos mediciones cualesquiera

El entrenador puede comparar cualquier par de Mediciones vigentes del historial, no solo consecutivas — útil para comparar "inicio de programa" contra "hoy" saltándose mediciones intermedias. La comparación calcula delta absoluto y relativo por variable presente en ambas; una variable ausente en cualquiera de las dos se omite de esa comparación específica, nunca se interpola.

Mejoras y retrocesos

VariableDirección de "mejora"
% grasa corporal, masa grasa, grasa visceralDisminuir — 🟠 producto, asume objetivo de reducción de grasa por defecto
Masa muscular, masa libre de grasaAumentar — 🟠 producto
Peso, IMCSin dirección de mejora asignada por defecto — depende enteramente del objetivo individual del cliente, que el sistema no conoce (02, "no alcance")
Límite explícito

BCS no conoce el objetivo del cliente (perder grasa, ganar músculo, mantenimiento) — las direcciones de "mejora" de la tabla son un default de producto para variables donde la dirección es razonablemente universal (menos grasa visceral es preferible en casi cualquier objetivo), nunca aplicadas a Peso o IMC, donde la dirección "correcta" depende del caso. El entrenador puede anotar el objetivo en Observaciones (03), pero el sistema no lo procesa algorítmicamente en v1 (17).

Casos límite

CasoComportamiento
Dos Mediciones con la misma fecha (registro duplicado accidental)Válido a nivel de dato — el sistema no lo bloquea, pero lo marca como valor sospechoso (03) para revisión del entrenador
Corrección de una correcciónAplica el mismo mecanismo: la Medición "corregida" anterior se anula, se crea una tercera — la cadena de anulaciones queda completa en la base de datos aunque el Reporte solo muestre la última vigente
Comparación entre una Medición con 15 variables y otra con solo 5Solo se comparan las variables presentes en ambas — nunca se asume 0 ni se omite la comparación entera
