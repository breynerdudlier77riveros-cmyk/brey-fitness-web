Módulo 04 · Modelo

Contrato de Entradas

Todo lo que el motor recibe, con su forma exacta, sus precondiciones y qué ocurre cuando una entrada llega incompleta o inválida. El motor no hace I/O propio (IN-P1) — todo lo de aquí llega ya resuelto por el orquestador (Motor BPS).

Objetivo

Que la firma de invocación del motor sea inambigua: cinco entradas, ni una más ni una menos, cada una con su contrato de forma y de validez.

Alcance

Las cinco entradas del pipeline (06, paso 1): Ventana de historial, Prescripción vigente, Veredicto de Recovery, Cadenas + capacidades, Fecha del ciclo.

No alcance

Cómo se construyen estas entradas (responsabilidad del Motor BPS y sus repositorios) — aquí solo se especifica la forma que deben tener al llegar.

Las cinco entradas

ENTRADA 1

Ventana de historial

Forma
Aparicion[] ordenado por fecha ascendente, por Slot
Origen
workout_logs reales (nunca prescripciones no ejecutadas)
Tamaño mínimo
4 apariciones para cualquier decisión macro (IN-P3); sin mínimo para decisión micro, que puede operar con 1
Precondición
Cada Aparición trae fecha, valores reales completos, RPE reportado si el Slot lo pedía, y flag de cumplimiento
ENTRADA 2

Prescripción vigente

Forma
{peso, repeticiones, series, tempo, descanso, rpeObjetivo, rir, duracion, volumen, densidad} — campos nulos permitidos solo si el Slot no los usa (ej. tempo en trabajo isométrico)
Origen
La última Decisión micro aplicada, o el default de programa si el Slot es nuevo
Puede ser null
Sí — Slot nunca antes prescrito; el motor trata esto como "usar default de cadena", no como error
ENTRADA 3

Veredicto de Recovery

Forma
{procede: boolean, tipo: "normal"|"descarga", razon: string}
Precondición
Obligatorio, no nulable — el orquestador debe consultar Recovery antes de invocar este motor (BPS-007/019). Su ausencia es un error de invocación, no un caso de negocio del Progression Engine.
ENTRADA 4

Cadenas + capacidades

Forma
Catálogo read-only: por Slot, la cadena de eslabones ordenada y la posición actual del usuario en ella
Origen
Knowledge Base
Mutabilidad
El motor nunca la modifica — solo lee la posición actual y, si decide avanzar, indica "siguiente eslabón" sin resolverlo a ejercicio
ENTRADA 5

Fecha del ciclo

Forma
Fecha explícita (BPS-022) — nunca Date.now() implícito dentro del motor
Por qué
Determinismo (P1/IN-P1): reprocesar el mismo ciclo días después debe producir la misma decisión, lo que exige que "ahora" sea un parámetro, no una llamada de sistema.

Estados inválidos de entrada

Estado inválidoTratamiento
Veredicto de Recovery ausenteError de invocación — el pipeline no arranca (06, paso "Validación")
Ventana con Aparición fuera de orden temporalError de invocación — la ventana debe llegar ya ordenada; el motor no ordena, solo valida orden
Ventana con menos de 4 apariciones y se solicita evaluación macroNo es error — es VENTANA_INSUFICIENTE (P6), decisión macro resuelve a "sostiene"
Prescripción vigente null en Slot nuevoNo es error — usa default de cadena (comportamiento esperado, no caso límite)
Fecha del ciclo anterior a la última Aparición de la ventanaError de invocación — viola causalidad; el orquestador nunca debería producir esto
