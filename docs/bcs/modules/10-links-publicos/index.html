Módulo 10 · Acceso y datos sensibles

Links Públicos

El diseño técnico del token de acceso: cómo se genera, qué expone exactamente la vista pública, y qué no expone jamás.

Formato del enlace

Ejemplo de forma: brey.fit/reportes/8Gd72hsQ — un token opaco al final de una ruta fija, sin ningún segmento que identifique al cliente por nombre o id secuencial.

Diseño del token

PropiedadEspecificación
GeneraciónAleatorio criptográficamente seguro — nunca derivado del clienteId, del nombre, ni de la fecha
AlfabetoAlfanumérico mixto (mayúsculas, minúsculas, dígitos)
Longitud mínima21 caracteres — 🟠 decisión de producto, mayor que el ejemplo ilustrativo de 8 caracteres del encargo original, elegida porque el modelo de seguridad de este enlace es enteramente "difícil de adivinar" (no hay contraseña ni rate-limiting garantizado en este documento, 08); un token corto sería vulnerable a enumeración por fuerza bruta a escala. Decisión formal en BCS-ADR-02 (16).
UnicidadUn token nunca se reutiliza, ni siquiera tras revocarse — un token revocado queda permanentemente inválido (IN-D4, 02)
IndexabilidadLa ruta pública incluye noindex para motores de búsqueda — no aparece en resultados de Google ni similares

Qué expone la vista pública

ExponeNo expone
El Reporte completo (04) del Cliente dueño del tokenDatos de contacto del cliente (teléfono, email, dirección) — el Reporte no los incluye por diseño
Nombre del cliente (para confirmar "este es mi reporte")El clienteId interno, ni ningún identificador de base de datos
Historial completo de Mediciones vigentes de ese Cliente únicamenteCualquier dato de cualquier otro Cliente del entrenador
Fotografías asociadas a las Mediciones de ese Cliente (si existen)Ningún control de edición, eliminación, ni generación/revocación de enlaces (08, IN-A1)

Sobre la expiración automática

No incluida en v1

Los enlaces no expiran automáticamente por tiempo — permanecen activos hasta revocación manual (09). Se consideró expiración automática (ej. 90 días) pero se descartó para v1 porque el caso de uso principal es que el cliente vuelva a consultar su progreso meses después con el mismo enlace, sin pedirle al entrenador uno nuevo cada pocos meses. Queda como candidato de configuración opcional en 14/17.

Casos límite

CasoComportamiento
Token revocado (09) accedido después de la revocaciónPágina de "enlace no disponible" — nunca un error genérico de servidor, siempre un mensaje explícito y sin revelar si el token alguna vez existió o no (08, mismo tratamiento que token inexistente para no filtrar información)
Cliente eliminado permanentemente (UC-04, 02) con un enlace aún activoEl enlace deja de resolver — se trata igual que un token inválido; eliminar un Cliente implica revocar en cascada cualquier EnlacePúblico asociado (16, invariante de integridad referencial)
Cliente archivado (no eliminado) con enlace activoEl enlace sigue funcionando normalmente — archivar no es eliminar (02, 09)
Alguien comparte la URL pública a un tercero no autorizadoFuera del control del sistema por diseño — el modelo de seguridad de este enlace es equivalente a compartir un PDF: quien tiene la URL, tiene acceso de lectura. Se documenta como riesgo aceptado en 11/17, no como bug.

Contraejemplos

  • El token NUNCA se construye a partir del clienteId, nombre, ni ninguna secuencia predecible.
  • La vista pública NUNCA muestra un enlace o botón hacia el panel del entrenador ni hacia ningún otro Cliente.
